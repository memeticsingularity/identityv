## 需求来源

用户提供两张游戏截图：
1. **充值档位表**：8 个档位（1/6/30/68/128/198/328/648 元），每个档位首次充值有首充赠礼，后续为常规赠礼
2. **珍宝概率公示**：赛季精华掉率（普通 31.7%、罕见 49.8%、独特 15.3%、奇珍 2.5%、稀世 0.7%），以及 10/60/200 抽保底规则

**核心诉求**：做一个"第五人格"风格的氪金 + 抽卡模拟器，支持充值、抽卡、记录查看，数据刷新不丢失。

### 阶段二：多池重构 + 保底修正

**用户反馈**：
1. 要有提示信息（已开多少件、多少金紫、还差多少保底）
2. 出金不应该顶紫保底
3. 记录太长，默认折叠
4. 精华非常多（第 42 赛季精华 3、一百多个精华），保底互不通用，要能切换精华池

**变更内容**：

#### 1. Store 重构为多精华池

```js
// v1.1 多池结构
const pools = ref({
  's42-e1': { drawCount, pity, drawRecords, rarityStats },
  's42-e2': { drawCount, pity, drawRecords, rarityStats },
  's42-e3': { drawCount, pity, drawRecords, rarityStats },
  // ... 共 9 个池子
})
```

每个池子完全独立：保底计数、抽卡记录、出货统计都是隔离的。

#### 2. 保底逻辑修正

**v1.0 错误实现**：出金时把金保底和紫保底一起清零了。  
**v1.1 正确实现**：
- 出 **稀世**：只清 `legendary` 和 `unique`，**不清 `epic`**
- 出 **奇珍**：只清 `epic` 和 `unique`，**不清 `legendary`**
- 出 **独特**：只清 `unique`
- 出 **普通/罕见**：三个计数器都自然累加

关键代码：
```js
if (rarity === 'legendary') {
  pool.pity.legendary = 0
  pool.pity.unique = 0
  // epic 不清零！金不顶紫保底
}
```

#### 3. 提示信息面板

在 GachaView 的抽卡按钮上方新增 `tips-panel`：
> 已开启 **N** 件，共获得：**N** 件稀世道具 和 **N** 件奇珍道具  
> 再开启 **N** 件必得奇珍以上道具 | 再开启 **N** 件必得稀世道具

#### 4. 记录折叠

抽卡记录默认只展示最近 **3 条**，底部有「展开全部」按钮。  
切换精华池后，记录自动切换为该池的独立记录。

#### 5. ProfileView 升级

- 新增「各精华池保底进度」卡片墙，点击可直接切换当前池
- 抽卡记录支持按精华池筛选
- 默认展示全部池子的混合记录（按时间倒序）

### 阶段三：概率公示交互优化

**用户反馈**：概率公示默认隐藏，类似游戏里 hover 才显示实际概率，不要常态展示大表格。

**变更**：

- 在精华名称标题旁添加 `InfoFilled` 小图标
- hover 时弹出 `el-popover`，内部用圆点 + 品质名 + 概率 + 说明的列表形式展示
- 弹窗宽度 420px，暗色背景适配主题

### 阶段四：持久化修复

**用户反馈**：刷新页面后回声、记录、保底全部归零。

**根因**：组合式 API 的 `defineStore` 不会自动持久化，需要在第三个参数加 `persist` 配置。

**变更**：
```js
export const useAppStore = defineStore('app', () => {
  // ...
}, {
  persist: {
    pick: ['echoes', 'totalRecharged', 'rechargeRecords', 'tierCounts', 'currentPoolId', 'pools'],
  },
})
```

**附带修复**：
- `generateItem` 的 ID 生成从全局计数器改为 `Date.now() + 随机数`，避免刷新后 ID 重复
- 池子初始化改为「补充缺失池子」模式，兼容未来新增精华池

---

### 阶段五：抽卡光效

**用户反馈**：抽卡时应该像游戏一样有光效——没出货蓝光，出货（紫/金）金光，然后再展示结果。

**变更**：

#### 光效覆盖层

在 `gacha-area` 内添加绝对定位的 `light-overlay`：
```vue
<div v-if="lightEffect" class="light-overlay" :class="lightEffect">
  <div class="light-core"></div>
  <div class="light-rays"></div>
  <div class="light-particles">
    <span v-for="n in 12" :key="n" class="particle" :style="particleStyle(n)"></span>
  </div>
</div>
```

#### 蓝光（普通/罕见/独特）
- 持续时间：1.2s
- 效果：柔和蓝色光晕扩散 + `conic-gradient` 射线旋转 + 12 颗蓝色粒子向外散射
- 触发条件：`getHighestRarity(results)` 返回 `unique` 或更低

#### 金光（奇珍/稀世）
- 持续时间：2s（奇珍）/ 2.5s（稀世）
- 效果：强烈金色核心爆发 + 双重光晕 + 密集射线旋转 + 金色闪烁粒子散射
- 触发条件：结果中包含 `epic` 或 `legendary`

#### 抽卡流程调整
```
点击抽卡 → 球旋转(0.8s/2s) → 判定光效 → 光效播放(1.2s~2.5s) → 光效消失 → 结果逐个弹出(200ms/个)
```

### 阶段七：充值记录美化

**用户反馈**：充值记录比较丑，希望能美化一下，也是默认展示最近 1-2 次，其他默认折叠。

**变更**：

#### 1. 卡片式布局替代表格

- 删除 `el-table`，改用自定义卡片列表
- 每条记录是一个横向卡片：左侧金额+标签，右侧回声+时间
- 首充记录有特殊的红色边框和渐变背景
- 悬停时有向右滑入的微动效

#### 2. 首充进度条

首充记录底部带有一条金色微光进度条，视觉上与普通记录区分。

#### 3. 折叠逻辑

- 默认只展示最近 **2 条**充值记录
- 超出后底部显示「展开全部 (N 条)」按钮
- 与抽卡记录的折叠逻辑保持一致
